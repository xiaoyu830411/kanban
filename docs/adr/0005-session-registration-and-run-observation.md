# 会话登记与运行状态观察

外部自开的 agent 会话可登记为任务，其运行状态由观察驱动镜像到看板。观察全部由本机 Agent 侧软件（launcher）承担——监视会话转录文件（jsonl）加进程存活探测，状态经既有 Agent API 上报；看板服务器保持被动（ADR-0002 不变：观察≠管理）。登记仅限白名单项目，建卡直接落进行中，标题取会话名。

状态判定：运行/空闲由最后一条 assistant 条目的 stop_reason 区分（tool_use=运行，end_turn=空闲）；终态为双信号——end_turn 后进程消失=完结，tool_use 中进程消失=中断；时间基准用最后条目的 ISO8601 timestamp 而非文件 mtime；空闲超阈值（默认 30 分钟，可配）视为完结。终态去向：登记型完结或中断均进待验收（中断加标注）；启动器拉起的完结进待验收、中断由 launcher 代行释放回待办。观察驱动的列变更允许回退（待验收↔进行中），已验收（done）不回退；验收依据为登记时的 git baseline 与终态时的改动清单，ADR-0001 人工验收门不变。

观察通道弃 hooks 选 jsonl 文件监视：零安装（不写用户 ~/.claude 配置）、claude 与 codex 会话同构、状态信息足够；代价是 jsonl 属无官方稳定性承诺的内部格式（类型值随版本演进），故解析一律防御式（未知类型忽略、单文件解析失败不影响观察器），并保留 hooks（官方契约）通道位——v1.1 如需「等待确认」徽标（jsonl 不可判定）以 Notification(permission_prompt) 补上。多 agent 支持按适配器接口（发现规则+解析规则）预留，v1 仅 claude code。

## Consequences

- 领域事件扩展 `task.registered`、`task.run_state_changed`（ADR-0004 公共契约；SSE 按 task.* 前缀过滤自动覆盖）
- CONTEXT.md 同步：「登记」入词汇表，任务出生方式 +1，「执行」起点改为「自认领或登记起」，「释放」补代行口径
- jsonl 格式漂移是长期风险：claude code 升级后需回归观察器；防御式解析与 hook 备份通道是双重缓解
- 状态列可能随观察往返（待验收↔进行中），活动流是往返的唯一审计线索
- 白名单默认空：全量登记的噪音会杀死这个功能
