# 看板不管理 Agent 进程

看板是被动协作面：Agent 通过 API 主动认领任务（pull），系统永不启动、停止或管理任何执行进程。v2 计划的主动触发也仅是 webhook 通知（告诉 Agent「有活儿了」），收到通知后仍是 Agent 自己来认领。原因：进程管理（生命周期、沙箱、重试、资源）复杂度深不见底，且与「任意 worker 通过 API 认领」的通用执行者模型矛盾——保持无状态的中立协作面，集成成本最低。

修订（2026-08）：待办卡片的「启动」按钮不违反本决策——点击是浏览器直接请求成员本机的启动器（Agent 侧软件，成员自行安装运行），看板服务器不经手、不感知，服务器仍是纯被动协作面。本决策约束的一直是看板服务器侧；启动器对任务的预认领与释放走的也是既有 Agent API。
