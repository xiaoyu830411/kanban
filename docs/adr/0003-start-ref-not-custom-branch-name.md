# 起始分支，而非自定义分支名

任务可指定「起始分支」（执行分支从哪个已有分支检出，见 CONTEXT.md），但执行分支名固定为 `task/<任务号>`，不接受自定义。分支名与任务号的固定映射是两条既有共识的锚点：分支保留供验收 diff（diff 归属靠任务号找回），GC 按任务号清 worktree。自定义名还会引入重名冲突与追踪负担，而真实工作流诉求是「从哪开始」（如 在 release/x 上执行），不是「叫什么名字」。改起始分支的重建以「现场干净」为前提：有未提交改动或分支上已有执行提交即拒绝，绝不删执行现场。

## Considered Options

- 自定义执行分支名——被否：破坏 task/<任务号> 映射锚点，还需处理重名与改名追踪
- 起始分支 + 固定执行分支名——采纳：满足「从哪检出」的诉求，不动分支保留与 GC 共识
- 不做分支字段——被否：多分支仓库无法指定起点，只能落在默认 HEAD
