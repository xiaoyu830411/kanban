# 插件内核与领域事件

内核只包含核心域（任务、看板、认领、空间、成员），其余功能一律按统一插件接口实现（注册 + 生命周期 + 订阅事件），随主程序编译部署。核心在任务创建 / 认领 / 移列 / 提交报告 / 验收 / 退回 / 评论等节点发领域事件，经进程内总线分发，插件订阅消费。v1 只有两个插件：auth（飞书扫码）与活动流。取舍：为一个 v1 小应用引入插件架构是刻意的过度设计——换取的是 v2 蓝图（飞书通知、外发 webhook、组织配置）都有现成的生长点，不必改内核。明确不做：运行时动态加载第三方插件（Cordis 式），那是另一个量级的复杂度。

## Consequences

- 领域事件清单是内核的公共契约，新增事件需谨慎（破坏插件兼容）
- 内核禁止直接依赖任何插件；插件间也不互相依赖，只通过事件与内核 API 协作
